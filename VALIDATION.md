# Проверка результатов и отчёта

Измерения получены пользователем на Ubuntu 22.04.5 ARM64 и переданы в
`AIMLLab4-results.zip`. Исходный SHA-256 архива и хеши всех 94 файлов записаны в
`reports/submission_manifest.json`. Данные, метрики, ответы API, логи и скриншоты
сохранены без изменения.

## Проверки при оформлении

- `scripts/validate_artifacts.py`: **50 проверок прошли**. Заново вычислены
  test MAE/RMSE/R² по 1906 прогнозам, воспроизведено разбиение seed=42,
  сверены исходные хеши, дубликаты, отсутствие пересечений, метрики/версии,
  API-ответы, Docker ID и healthcheck.
- Дополнительно проверены пять листов XLSX: это пять перестановок одной таблицы.
  Для обучения использован только Sheet1.
- `pytest -q`: **25 passed**. В первоначальной установке было 14 тестов; после
  исправления RH — 17, затем добавлено 8 проверок компаратора ответов сборщика.
- `lab4.ipynb`: все **14 кодовых ячеек выполнены**, ошибок нет. Notebook проверяет
  сохранённые артефакты; обучение и Docker заново не выполняются.
- `report.html` открыт в Chromium, все **16 иллюстраций** загружены: 14 исходных
  скриншотов и два графика. Изображения встроены, формулы записаны без зависимости
  от MathJax. Markdown и notebook также содержат результаты и подписи.

## Почему в исходном сборщике есть false

Исходный `reports/evidence_status.json` оставлен неизменным. Его
`update_verified=false` вызван точным сравнением float-ответов v2 и Compose:
`465.65352000000087` и `465.6535200000009`. Разница — один ULP,
**5.684341886080802e-14 MW**, при одинаковых model SHA-256 и image ID.

Функциональные проверки Ubuntu с `rtol=1e-10, atol=1e-9` прошли. Независимая
проверка сохранена в `reports/verification.json`. Компаратор сборщика исправлен
для будущих запусков; старый код сохранён в `reports/submitted_collect.py.before`.
Исходный отрицательный флаг не подменяется результатом новой проверки.

## Ограничения проверки

В ZIP намеренно отсутствуют model.joblib и SQLite/артефакты MLflow. Отчёт
проверяет сохранённые свидетельства, а не обращается к живому сервису;
хеши моделей сопоставляются по метаданным, не вычисляются по отсутствующим бинарным
файлам. Полная остановленная резервная копия хранится отдельно у исполнителя.

Изолированные проверки стартового комплекта на синтетических данных в Debian
не используются как результаты CCPP. Для нового обучения предназначен
`scripts/create_run.sh`: он сохраняет опубликованные доказательства и готовит
чистую рабочую папку. См. README.
