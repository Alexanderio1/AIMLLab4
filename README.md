# Лабораторная №4: MLOps, вариант 17 — CCPP

**Это комплект для выполнения работы, а не отчёт с готовыми измерениями.**
Запуски на ваших данных и Ubuntu создадут результаты в `reports/`.
Вход в VS Code / Codex, API-ключи и платные облачные сервисы не нужны.

## Что потребуется

- Ubuntu 22.04 или 24.04 LTS. Поддерживаются ARM64 (Mac M1/M2 в виртуальной машине) и AMD64.
- Python проекта — 3.12. На Ubuntu 22.04 установщик автоматически подготовит отдельный Python 3.12.14, сохранив системный Python 3.10.
- Желательно выделить виртуальной машине 4 CPU, 6–8 ГБ RAM и 12 ГБ свободного диска.
- Интернет: UCI, PyPI, GitHub Releases (Python), Docker Hub и официальный репозиторий Docker.
- Два терминала не обязательны: скрипт сам запустит локальный MLflow.
- Все команды ниже выполняются в **Ubuntu**, а не в терминале macOS.
- Скриншоты делайте на самой Ubuntu. Сохраните их в `screenshots/`.

## 1. Распаковка

Скачайте [AIMLLab4-starter.zip](https://github.com/Alexanderio1/AIMLLab4/raw/refs/heads/main/downloads/AIMLLab4-starter.zip)
в Ubuntu (или перенесите с Mac через общую папку).
Откройте терминал: Ctrl+Alt+T. Сначала:

```bash
cat /etc/os-release
uname -m
python3 --version
sudo apt update
sudo apt install -y unzip git curl ca-certificates python3-venv python3-pip
```

Далее распакуйте архив через файловый менеджер. Откройте терминал в папке
`AIMLLab4`, где лежит этот README. При распаковке командой (путь к загрузкам
может называться `Downloads` или `Загрузки`):

```bash
mkdir -p ~/projects
unzip ~/Downloads/AIMLLab4-starter.zip -d ~/projects
cd ~/projects/AIMLLab4
pwd
ls
```

**Если такая папка уже существует и в ней есть ваша работа, используйте другую
папку и не перезаписывайте файлы.** Все дальнейшие команды запускайте из
получившегося каталога проекта.

На Ubuntu 22.04 вывод `Python 3.10.x` на этом этапе нормален. Не заменяйте
`/usr/bin/python3`: скрипт установки создаст отдельное окружение с Python 3.12.
На Ubuntu 24.04 используется доступный Python 3.12. Другие версии ОС требуют
отдельной проверки.

Вместо скачивания архива можно клонировать исходники:

```bash
mkdir -p ~/projects
git clone https://github.com/Alexanderio1/AIMLLab4.git ~/projects/AIMLLab4
cd ~/projects/AIMLLab4
```

Если папка уже занята, выберите новое имя: не перезаписывайте существующую работу.

## 2. Установка Docker и зависимостей

```bash
bash scripts/install_docker_ubuntu.sh
bash scripts/install.sh
```

Первый скрипт использует официальный apt-репозиторий Docker с поддержкой ARM64.
Если Docker и Compose уже работают, он ничего не переустанавливает. При
конфликтующих пакетах он остановится, ничего не удаляя; пришлите вывод ошибки.
Второй скрипт создаёт `.venv`, устанавливает точный lock-файл и проверяет
зависимости и API-контракт. При отсутствии Python 3.12 сначала устанавливается
`uv==0.13.5` в частную папку `.tools/uv`, затем скачивается CPython 3.12.14
в `.tools/python`. Системные Python и pip не изменяются; PPA не требуется.
Загрузка Python и пакетов использует проверку TLS. `sudo pip` не используется.

После установки проверяйте именно интерпретатор проекта:

```bash
.venv/bin/python --version
python3 --version
```

На Ubuntu 22.04 ожидается соответственно 3.12.14 и прежний 3.10.x.

**Скриншот 01:** `cat /etc/os-release`, `uname -m`, Python, версии Docker / Compose.
**Скриншот 02:** успешное завершение установки, `pip check` и тестов.

## 3. Данные, шесть экспериментов, Model Registry, итоговый test

```bash
bash scripts/run.sh experiments
```

Этап загружает официальный архив UCI, использует первый лист
`Folds5x2_pp.xlsx`, проверяет колонки, 9568 исходных строк, пропуски и единицы.
Точные повторы целых строк удаляются. Одинаковые векторы признаков группируются
при разбиении, даже если PE различается. Разбиение примерно 60/20/20: train,
validation, test. Индексы исходных строк, CSV, SHA-256 и seed сохраняются.
Остальные листы не объединяются и не используются.

Если автоматическая загрузка недоступна, скачайте ZIP кнопкой Download на
странице UCI, сохраните его **без распаковки** как `data/raw/ccpp.zip` и повторите
команду. Не используйте CSV неизвестного происхождения:
https://archive.ics.uci.edu/dataset/294/combined+cycle+power+plant

Запускаются три Ridge (`alpha=0.1, 1, 10`) и три RandomForestRegressor
(120/200/250 деревьев, глубины 8/16/без ограничения). Параметры, метрики,
единицы, split, исходник, графики и Pipeline сохраняются в MLflow.

Выбор — минимум MAE на validation; RMSE и R² дополнительные. Для Ridge
StandardScaler обучается только на train. Для RF преобразование passthrough.
После выбора модель **не переобучается**: ровно этот артефакт оценивается на test.
Test не используется для подбора параметров.

Registry `ccpp-power` получает две версии: `baseline` — лучший запуск другого
алгоритма; `selected` — победитель по validation MAE. Alias `champion` сначала
указывает на selected. Реальные номера записаны в `reports/registry.json` и
могут отличаться от 1 и 2 после неполных повторных запусков.

Откройте браузер **в Ubuntu**: `http://127.0.0.1:5000`.
Выберите эксперимент `lab4-ccpp-variant17`; покажите колонки MAE/RMSE/R².
Скопируйте run_id из таблицы, если нужно. CSV и JSON уже сохранены автоматически.

**Скриншот 03:** аудит данных с числом строк и разбиением в терминале.
**Скриншот 04:** таблица MLflow со всеми шестью запусками, параметрами и MAE.
**Скриншот 05:** Models → `ccpp-power`, две версии и alias champion.
**Скриншот 06:** итоговая таблица/вывод test MAE, RMSE, R² и run_id в терминале.

Если вывод ушёл вверх, покажите его снова:

```bash
cat reports/data_audit.json
.venv/bin/python -c 'import pandas as pd; print(pd.read_csv("reports/experiments.csv").to_string(index=False))'
cat reports/test_metrics.json
```

Отсутствие временных меток ограничивает интерпретацию: это прогноз мощности по
параметрам среды, а не доказанная точность прогноза будущих периодов.

## 4. Образ v1 и работа API

Обновите разрешение sudo (не запускайте весь скрипт через sudo):

```bash
sudo -v
bash scripts/run.sh v1
```

Экспортируется baseline вместе с преобразованиями, назначается champion,
собирается образ `ccpp-api:v1`, затем запускается `ccpp-lab17-api` на порту 8000.
Базовый `python:3.12-slim` мультиархитектурный. Скрипт сохраняет его digest и
использует **тот же digest** для v2, без эмуляции AMD64 на ARM64.
Dockerfile устанавливает отдельный lock-файл runtime-зависимостей; версии
библиотек предсказания совпадают с обучением. В контейнере нет сервера MLflow.

Проверка делает корректный запрос, сравнивает API с загруженным локально
экспортированным Pipeline (`rtol=1e-10`, `atol=1e-9`), проверяет `/metadata`,
`/docs`, ошибочные запросы (ожидается 422) и **реальный Docker healthcheck**.

**Скриншот 07:** конец сборки, тег v1, `ALL API CHECKS PASSED` и healthy.

## 5. Обновление до v2

```bash
sudo -v
bash scripts/run.sh v2
```

Экспортируется selected, champion переключается на неё. Новый образ
`ccpp-api:v2` заменяет v1. Повторяются проверки. Обучение не выполняется.

**Скриншот 08:** версия модели, ответ API, успешные проверки и healthy для v2.

## 6. Откат к v1 без обучения и сборки

```bash
sudo -v
bash scripts/run.sh rollback
```

Повторно используется уже собранный `ccpp-api:v1`. Alias возвращается на
baseline. Исходный экспорт не изменяется. Проверка сверяет модель и предсказания.

**Скриншот 09:** номер старой версии, ответ API, успешные проверки, healthy.

В `reports/api_v1.json`, `api_v2.json`, `api_rollback.json` сохраняются версии,
run_id, хеши моделей, запросы, ответы и отклонения от локальных предсказаний.

## 7. Docker Compose

```bash
sudo -v
bash scripts/run.sh compose
```

Одиночный контейнер удаляется, Compose запускает уже собранный образ v2.
Champion снова указывает на selected. `compose up --wait` и отдельная проверка
подтверждают healthy, затем API снова сравнивается с локальной моделью.

**Скриншот 10:** `docker compose ps`, healthy и успешные проверки API.
**Скриншот 11:** браузер `http://127.0.0.1:8000/docs`, выполненный POST /predict.
При желании раскройте в Swagger также ошибочный запрос с ответом 422.

### Контракт API

```json
{"instances": [{"AT": 20.0, "V": 50.0, "AP": 1010.0, "RH": 70.0}]}
```

Ответ содержит `model_version`, `predictions_MW`, `unit: "MW"`.
Каждый объект содержит ровно AT, V, AP, RH; от 1 до 1000 строк в запросе.
Все значения — конечные JSON-числа (не строки/булевы), V и AP положительны,
RH от 0 до 100. AT — °C, V — cm Hg, AP — mbar, RH — %, PE — MW.
Эти проверки не заменяют анализ сдвига распределения за пределами датасета.

Дополнительный ручной запрос:

```bash
curl -sS http://127.0.0.1:8000/metadata
curl -sS -X POST http://127.0.0.1:8000/predict \
  -H 'Content-Type: application/json' \
  --data-binary @exported_models/v2/sample_request.json
```

## Повторный запуск и остановка

MLflow запускается автоматически; после `collect` его можно снова открыть:

```bash
.venv/bin/python scripts/mlflow_server.py start
```

Повторное обучение для просмотра UI не требуется. Процессы не переживают
перезапуск Ubuntu. Существующие образы и файлы сохраняются. Для остановки:

```bash
sudo -v
bash scripts/run.sh stop
```

Для полного нового опыта распакуйте комплект в **новую папку**. При неудачном
этапе пришлите текст ошибки и соответствующий `reports/logs/*.log`, не удаляйте
Docker-хранилище и не запускайте `docker system prune`.

Снимок MLflow восстанавливается в тот же путь: сохранённые артефакты используют
локальную абсолютную директорию сервера. Для другой машины/пути предпочтителен
документированный повторный запуск с сохранёнными исходными данными, split и
lock-файлом. Не утверждается, что бинарные RF-модели побитово одинаковы на
разных архитектурах; численные предсказания проверяются с допуском.

## Структура

- `src/workflow.py`: загрузка, аудит, split, эксперименты, Registry, test, экспорт, API-check.
- `src/app.py`: FastAPI и проверка целостности модели при старте.
- `scripts/`: установка, управление MLflow, этапы Docker, сбор доказательств.
- `tests/`: синтетические проверки отсутствия утечки, API и повреждённой модели.
  Эти фикстуры **не являются результатами экспериментов лабораторной**.
- `Dockerfile`, `compose.yaml`, lock-файлы: воспроизводимое окружение.
- `data/`, `reports/`, `exported_models/`, `mlflow-data/`: создаются при выполнении.
